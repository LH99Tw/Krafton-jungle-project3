# 《5일 뒤 마왕》 0.2 3인 개발 협업 역할분담 보고서

> 문서 버전: v2.0
> 역할: 시스템 기획 / 레벨 디자인 / 백엔드·서버
> 기술 기준: Next.js Node + Phaser + Colyseus + PostgreSQL + protocol v2
> 기획 기준: `0.2버전_명세서.md`, `0.2버전_밸런스_데이터.md`

## 1. 협업 결론

```text
시스템 기획 ─ 밸런스·경제·성장 규칙 ─┐
                                       ├→ packages/game-core → Colyseus 권위 판정
레벨 디자인 ─ seed·방·경로·웨이브 ───┘                ↓
                                                    protocol v2
                                                       ↓
                                          Phaser 렌더링 · React HUD
                                                       ↓
                                             PostgreSQL 결과 저장
```

- 시스템 담당은 수치·효과·경제·성장 곡선의 단일 소유자다.
- 레벨 담당은 방 구조·경로·배치·시드 안전성의 단일 소유자다.
- 백엔드 담당은 네트워크 계약·서버 권위·인증·저장·배포의 단일 소유자다.
- 순수 규칙은 `packages/game-core`, 네트워크 타입은 `packages/protocol`을 단일 원본으로 삼는다.
- Phaser 로컬 상수는 최종 판정에 사용하지 않는다.

## 2. 공통 목표와 완료 기준

### 2.1 0.2 목표

1. `solo`는 실제 사용자 1명, `coop`은 실제 사용자 3명으로 시작한다.
2. AI 동료 없이 3구역 룸맵과 최종 보스를 완주한다.
3. 서버가 이동 유효성·전투·AI·경제·성장·드롭·건설·승패를 판정한다.
4. 같은 seed와 명령 순서는 같은 맵·드롭·draft 결과를 만든다.
5. 세 브라우저에서 동일한 권위 상태가 보인다.

### 2.2 공통 수용 기준

- 구역마다 5×5 중 정확히 15개 방과 유효 경로가 존재한다.
- prototype/full의 같은 상태기계를 반복 검증할 수 있다.
- 시스템·레벨 데이터 ID가 protocol과 Schema에서 동일하다.
- 클라이언트 변조로 피해·골드·드롭·보스 입장·승패를 만들 수 없다.
- 변경 PR에 목적, 영향 범위, 검증 명령, 재현 seed, 남은 리스크를 남긴다.

## 3. 역할 A — 시스템 기획

### 3.1 책임

- 클래스별 공격·스킬·사거리·조준 원뿔 밸런스
- 적·게이트·보스·시설의 HP·피해·속도·비용
- 팀 XP·레벨30·10/20/30 전직·개인 증강
- 자원 생산, 드롭 확률, 장비 기본 스탯과 특수 옵션
- 솔로/3인, easy/normal/hard 보정
- 테스트 결과 분석과 한 축씩의 수치 조정

### 3.2 소유 파일

```text
Document/0.2버전_밸런스_데이터.md
packages/game-core/src/v02/progression.ts
packages/game-core/src/v02/equipment.ts
향후 packages/game-core/src/content/{classes,enemies,buildings,waves}.ts
```

클라이언트 `apps/web/src/game/content`는 마이그레이션 기간의 표시·레거시 참고 계층이며 서버 수치 원본이 아니다.

### 3.3 필수 산출물

| 산출물 | 완료 기준 |
|---|---|
| 서버 클래스 표 | HP·공격·방어·속도·주기·사거리·Q/E 전체 승인 |
| 적/게이트/보스 표 | 구역·난이도·파티 모드별 계산식 포함 |
| 성장 표 | XP, 일반10종, 클래스별 전직5종, stack 계산식 |
| 장비 표 | 슬롯별 100% 기준값, 옵션 풀, 중복 규칙 |
| 경제 표 | 자원 +1/5초, 시설 비용, 보상·손실 곡선 |
| 플레이테스트 리포트 | seed·인원·도달 레벨·클리어 시각·잔여 HP 기록 |

### 3.4 우선 결정 항목

1. 임시 서버 클래스/베이스 수치 승인 또는 재산정
2. 공격속도와 % stack 계산식
3. 치명타 기본 확률·배율
4. 장비 슬롯별 100% 기준 스탯과 옵션 풀
5. 솔로/3인 적·보스 보정

### 3.5 테스트

- 클래스별 30초 단일/광역 DPS
- 레벨 2~30 모든 draft에서 합법 후보 3개
- 히든 장비 전후 전투력 변화
- 자원 12방 최대 생산이 건설 경제를 무력화하지 않는지 확인
- prototype과 full에서 정적 리스폰의 XP 파밍 속도 비교

## 4. 역할 B — 레벨 디자인

### 4.1 책임

- 3구역 5×5 그리드와 15방 구성
- 시작 `(0,4)`, 게이트 `(4,0)`, 구역1 우측·상단 고정 통로
- 자원4·정적4·빈2·중앙 웨이포인트1·히든2 배치
- 모든 방 연결, 히든 degree1, 최심부 판정
- 방 템플릿, door 위치, 충돌, 동적 몬스터 경로
- 웨이포인트·건설 구획·보스 아레나 공간 설계
- 분산 탐색용 미니맵·핑 정보 설계

### 4.2 소유 파일

```text
packages/game-core/src/v02/map.ts
향후 packages/game-core/src/levels/
├─ room-templates.ts
├─ wave-routes.ts
├─ build-zones.ts
└─ boss-arena.ts
apps/web/src/features/game/RoomMiniMap.tsx  # 표현 규격 공동 리뷰
```

레벨 데이터는 시스템 담당의 enemy/reward ID를 참조하되 수치를 복제하지 않는다.

### 4.3 필수 산출물

| 산출물 | 완료 기준 |
|---|---|
| 방 템플릿 | 입구·출구·전투/자원 공간·안전 여백 정의 |
| map invariant | 1,000개 이상 seed property test |
| 경로 표 | 게이트→시작 웨이포인트→베이스 유효 경로 |
| 웨이포인트 구획 | 전원 점유 가능, 출입구와 겹치지 않음 |
| 건설 구획 | 길 완전 차단 불가, UI 진입 경계 일치 |
| 보스 아레나 | 패턴 예고·안전지대·3인 이동 공간 검증 |

### 4.4 공간 체크리스트

- 시작에서 게이트까지 항상 도달 가능한가?
- 히든 방이 필수 진행로를 막지 않는가?
- 중앙 웨이포인트가 시작·게이트에 인접하지 않는가?
- 3명이 점유 범위에 서도 door를 막지 않는가?
- 서로 다른 방의 팀원 위치와 위험을 미니맵으로 이해할 수 있는가?
- 동적 몬스터가 방 전환 중 경로를 잃지 않는가?

## 5. 역할 C — 백엔드·서버

### 5.1 책임

- Next.js 서버 세션, game-ticket, Colyseus Room, PostgreSQL 유지
- protocol v2 명령 검증과 Schema 상태 동기화
- `packages/game-core` 규칙을 20Hz 시뮬레이션에 통합
- 솔로1/협동3 매치메이킹·Room 잠금·재접속
- 자동 공격·AI·자원 tick·웨이포인트·장비·건설 권위 처리
- 중복 seq, 이중 구매, 이중 드롭, 다른 사용자 소유권 공격 방지
- match 결과 transaction, 로그, health check, 배포·롤백

### 5.2 소유 파일

```text
packages/protocol/src/index.ts
apps/game-server/src/{party-room,state,index}.ts
packages/game-core/src/index.ts            # orchestration, 공용 규칙 리뷰 필수
packages/db/src/{schema,repositories}.ts
packages/auth/src/index.ts
apps/web/src/game/transport/ColyseusTransport.ts
deploy/ , compose*.yml , Caddyfile
```

### 5.3 현재 경계

| 영역 | 상태 |
|---|---|
| 인증·세션·티켓·DB | 구현 |
| PartyRoom·입력·페이즈·결과 | 기반 구현 |
| protocol v2·확장 Schema | 기반 구현 |
| v02 맵·드롭·성장 순수 규칙 | 규칙 준비 |
| 전투·AI·자원·이동·장비·건설 | 서버 통합 대기 |

### 5.4 서버 테스트 우선순위

1. v1·잘못된 payload·추가 필드·중복/out-of-order seq 거부
2. solo 1명과 coop 3명 시작, 진행 후 중도 참가 거부
3. 세 클라이언트 동일 seed·맵·entity 상태
4. 동적 몬스터 target에 player ID가 들어가지 않음
5. 웨이포인트 이탈·사망·연결 종료 시 5초 초기화
6. 자원 tick과 구매의 중복 차감/지급 방지
7. 다른 사용자의 drop 장착·중복 장착 거부
8. 클라이언트 결과 위조 불가와 결과 transaction 멱등성

## 6. 공통 계약과 변경 권한

| 변경 | 작성 | 필수 리뷰 | 검증 |
|---|---|---|---|
| 클래스·증강·장비 수치 | 시스템 | 백엔드 | unit/property + 플레이테스트 |
| 방·door·경로·웨이브 | 레벨 | 백엔드 | map/path property |
| protocol·Schema | 백엔드 | 시스템 또는 레벨 중 영향 담당 | client/server contract |
| 새 enemy/room/item ID | 소유 담당 | 나머지 2명 | ID 참조·seed 재현 |
| 페이즈·경제 루프 | 시스템 | 레벨+백엔드 | E2E 런 |
| 배포·DB migration | 백엔드 | 1명 이상 | staging·rollback |

- 공통 ID는 `lower-kebab-case`, network ID는 Room 안에서 유일해야 한다.
- 문서와 코드 값을 동시에 바꾸고 변경사항 문서에 기록한다.
- 랜덤 규칙 변경은 과거 seed 재현에 영향을 명시한다.
- protocol breaking change는 version을 올리고 구버전 거부 test를 추가한다.

## 8. PR·커밋 규칙

- 커밋: `feat(system):`, `feat(level):`, `feat(server):`, `fix:`, `test:`, `docs:`.
- 한 PR은 한 목적을 유지한다.
- PR 본문: `목적 / 영향 파일 / 계약 변경 / 검증 / 재현 seed / 남은 리스크`.
- protocol·Schema·공용 ID는 관련 담당자 2명 이상 리뷰한다.
- 밸런스 PR도 수치 전후의 측정값을 첨부한다.
- migration은 생성 SQL과 rollback 가능성을 리뷰하고 운영에서 `push`를 사용하지 않는다.

## 9. 의사결정 규칙

- 수치 충돌: 시스템 담당이 원본표를 제시하고 레벨·백엔드가 공간/검증 영향을 확인한다.
- 맵 충돌: 레벨 담당이 경로 불변조건을 지키고 시스템 담당이 보상을 조정한다.
- 네트워크 충돌: 백엔드 담당이 서버 권위·보안을 보장하고 체감 지연은 공동 테스트한다.
- 30분 내 결론이 없으면 현재 기준값을 유지하고 대안·결정자·기한을 `0.2버전_변경사항.md`에 남긴다.
- 발표 직전에는 신규 콘텐츠보다 서버 일치, 세션 완주, 재현성을 우선한다.

## 11. 역할별 Definition of Done

### 시스템

- 서버 클래스·적·시설·장비·성장 원본표가 승인됐다.
- 일반26회와 전직3회의 성장 곡선이 끊기지 않는다.
- solo/coop·난이도별 기대 완주 지표가 기록됐다.

### 레벨

- 모든 검증 seed에서 15방·전체 연결·히든 degree1이 유지된다.
- 방 템플릿·door·웨이포인트·건설·동적 경로가 실제 화면과 일치한다.
- 분산 탐색과 보스 아레나를 3명이 플레이할 수 있다.

### 백엔드

- Colyseus가 전투·AI·경제·성장·이동·건설·승패를 소유한다.
- 세 클라이언트가 같은 권위 상태를 본다.
- 인증·재접속·악성 입력·중복 요청·결과 저장 test가 통과한다.
- 다른 팀원이 배포·롤백할 수 있는 런북과 환경 계약이 있다.

## 12. 다음 회의 안건

1. 서버 클래스·베이스 최종 수치
2. 장비 100% 기준값과 특수 옵션 풀
3. 재접속 20초 동안 무적·제거 정책
4. 빈 방 저주기 시뮬레이션 최적화 여부
5. 익명 게스트·Google·초대코드 중 공개 인증 방식
6. 중앙 봉인 발판 협동 콘텐츠 포함 여부
