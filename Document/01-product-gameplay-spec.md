# 《5일 뒤 마왕》 제품·게임플레이 명세

> 상태 기준: 2026-08-12 / 프로토콜 v10 / 현재 빌드

## 1. 제품 정의

《5일 뒤 마왕》은 브라우저에서 실행되는 서버 권위형 협동 로그라이트 액션 RPG다. 플레이어는 5일 동안 세 구역을 탐색하고 게이트의 침공을 막으며 성장한 뒤 마왕을 처치한다.

핵심 경험은 다음 세 가지다.

- 탐색과 베이스 방어 사이의 시간 배분
- 자동 공격과 클래스 스킬을 이용한 위치·조준 전투
- 공유 성장과 개인 장비를 조합한 파티 진행

지원 화면 크기의 기준은 1280×720이며 현재 입력은 키보드와 포인터를 전제로 한다. 모바일 조작은 지원 범위가 아니다.

## 2. 사용자 흐름

1. 접근 화면에서 Cognito/Google, 개발 로그인 또는 공개 게스트 세션을 선택한다.
2. 전체 로비에서 방을 만들거나 참가한다. 솔로 원정은 실제 사용자 1명과 서버 AI 두 명으로 구성된다.
3. 협동 방은 최대 3명이며 준비 후 캐릭터를 선택한다.
4. 게임 티켓을 발급받아 Colyseus 게임 룸에 입장한다.
5. 탐색·전투·성장·구역 이동·보스전을 진행한다.
6. 승리, 패배, 포기 또는 35분 제한으로 종료한다.
7. 서버가 개인 기여 통계를 포함한 결과를 저장하고 결과 화면을 표시한다.

## 3. 모드와 파티

| 항목 | 현재 규칙 |
|---|---|
| 파티 모드 | `solo`, `coop` |
| 솔로 | 인간 1명, 서버 AI 2명 |
| 협동 | 실제 사용자 최대 3명 |
| 세션 모드 | `prototype`, `full` |
| 난이도 | `normal`, `hard` |
| 클래스 | 검사, 궁수, 마법사 |
| 중도 참가 | 게임 시작 후 신규 사용자 참가 불가 |
| 재접속 | 비정상 이탈 후 최대 60초 예약 |
| 이탈 인계 | 다른 인간이 남아 있으면 서버 AI가 캐릭터를 인계 |

모든 인간이 떠나면 원정은 `abandoned`로 종료된다. 같은 계정의 새 연결은 기존 연결을 교체한다.

## 4. 세션과 승패

페이즈는 `lobby → day → night` 순으로 교차한다. 5일 이후 마왕을 처치하지 못하면 패배한다. 보스 방에 진입하면 `boss` 페이즈로 전환한다.

승리 조건:

- 마왕 HP를 0으로 만든다.

패배·종료 조건:

- 베이스 HP가 0이 된다.
- 5일 제한을 넘긴다.
- 원정 생성 후 35분을 넘긴다.
- 모든 인간 플레이어가 떠난다.

## 5. 월드와 진행

온라인 게임은 편집기로 제작해 컴파일한 공식 맵을 사용한다.

| 공식 맵 | 값 |
|---|---:|
| 전체 방 | 48 |
| 구역 1 / 2 / 3 | 14 / 19 / 15 |
| 연결 | 49 |
| 이동 가능 사각형 | 98 |
| 월드 크기 | 16,640×6,820 |
| 게이트 | 8 |
| 보스 방 | 1 |

공식 맵 revision은 `618d637b67143efe4fa1cabd2676de55a1c3788f595544b8e2c50dd36649c49b`다. 클라이언트와 서버 revision이 다르면 입장을 거절한다.

구역 진행 규칙:

1. 구역 1 베이스에서 시작한다.
2. 방에 진입하면 파티 탐색 상태에 기록한다.
3. 현재 구역의 모든 게이트를 파괴하기 전에는 다음 구역 진입을 막는다.
4. 플레이어가 활성 웨이포인트 반경 안에서 발견한 웨이포인트 마커를 선택하면 3초 동안 이동을 준비한 뒤 해당 지점으로 순간 이동한다.
5. 구역 3 게이트를 모두 파괴한 뒤 보스 방으로 이동한다.

절차 생성형 5×5·구역당 15방 규칙은 `GameCore`의 로컬/테스트 대체 월드에만 적용된다. 온라인 공식 맵의 제품 규칙이 아니다.

## 6. 조작과 전투

| 입력 | 의도된 동작 |
|---|---|
| WASD | 이동 |
| 포인터 | 조준 방향 |
| Q/E | 현재 웹 직접 입력 없음; 클래스 Q/E는 쿨다운마다 자동 발동 |
| Space | 대시 계약이나 현재 온라인 입력 매핑 결함 존재 |
| B | 활성 웨이포인트 귀환 요청 |

기본 공격과 Q/E 스킬은 자동이다. 서버는 살아 있고 공격 가능한 적을 거리와 조준 원뿔로 필터링한 뒤 가장 가까운 대상을 선택한다. 원뿔 안에 대상이 없으면 사거리 내 가장 가까운 적을 사용한다. 거리 동률은 안정적인 ID 순서로 결정한다.

밤에는 플레이어 시야가 800에서 420으로 줄고, 공격 사거리는 기본값의 65%가 된다. 이동, 충돌, 공격, 치명타, 스킬, 피해, 사망과 적 AI의 최종 판정은 서버가 소유한다.

## 7. 적과 방어

- 정적 적: 자기 생성 방 안에서 추격·공격하고 일반형만 모드별 시간 후 부활한다.
- 히든 적: 원거리 패턴을 사용하며 처치 후 부활하지 않는다.
- 게이트 적: 위협도 기반 표적과 패턴 공격을 사용하며 침략자 웨이브의 근원이다.
- 침략자: 실제 연결 통로를 따라 베이스로 이동하고 플레이어와 베이스를 공격한다.
- 보스: 부채꼴·바닥 패턴을 사용하며 처치 시 승리한다.

침략자는 최대 동시 개체 수와 대기열을 제한한다. 서버는 플레이어와 가까운 개체를 높은 주기로, 먼 개체를 낮은 주기로 갱신할 수 있지만 권위 시계와 전투 규칙은 유지한다.

## 8. 성장·보상·장비

- 파티 XP와 레벨은 공유한다.
- 레벨업마다 각 플레이어에게 결정론적인 개인 증강 선택지 3개를 제공한다.
- 10, 20, 30레벨에는 클래스 전용 마일스톤 증강을 제공한다.
- 자원 방 중앙에 처음 진입하면 파티원별 개인 장비 하나를 생성한다. 재입장·재접속으로 다시 지급하지 않는다.
- 히든 적 처치 시 플레이어별 개인 장비를 생성한다.
- 개인 드롭과 증강 draft는 소유자에게만 전송한다.
- 장비 슬롯은 무기, 방어구, 장신구다.
- 개인 인벤토리는 6칸이며 장착, 교체, 폐기가 서버 규칙으로 처리된다. 가득 찬 상태에서는 장비가 바닥에 남아 폐기 후 다시 획득할 수 있다.

특수 방은 장비 보급 자원 방, 신전, 함정, 체크포인트, 제단으로 구성된다. 장비 개인 지급, 신전 채널링, 개인 부활 체크포인트와 제단 능력치 교환을 모두 서버가 판정한다. 구형 제작 맵의 `shop`·`gold`는 `resource`, `gamble`은 `altar`로 변환한다. 장비 비교와 특수 옵션의 실제 효과 풀은 아직 완성되지 않았다.

## 9. AI 동료

솔로 원정과 이탈 인계 캐릭터는 서버 AI가 조종한다.

- 수비 AI는 베이스를 순찰하고 침입자를 요격한다.
- 추종 AI는 인간 리더와 간격을 유지하고 통로 경로를 따라 이동한다.
- AI는 증강을 자동 선택하고 더 강한 비전용 장비를 양보할 수 있다.
- AI도 사망, 부활, 이동 점유와 전투 규칙을 동일하게 적용받는다.

경로 선택은 실제 통로 길이와 충돌 가능성을 사용한다. 직선 이동이 막히면 A* 경로를 사용하며, 재계획과 정체 복구는 제한된 예산 안에서 수행한다.

## 10. UI 범위

현재 연결된 화면:

- 접근·로그인·게스트 화면
- 전체 로비, 방 목록, 방 채팅, 전체 채팅
- 캐릭터 선택
- Phaser 게임 화면과 HUD
- 파티 생명력, 페이즈, 독립 인벤토리 버튼, 방 단위 탐색·카테고리 마커·확장 보기를 지원하는 미니맵
- 개인 증강 draft
- 개인 드롭, 인벤토리, 장착과 특수 방 상호작용 HUD
- 승패·개인 기여 결과 화면
- 개발 전용 맵 에디터와 증강 실험실

## 11. 현재 제한과 알려진 결함

| 구분 | 상태 |
|---|---|
| 서버 건설 | 프로토콜·Schema만 존재하며 `BUILD_NOT_READY` 반환 |
| 구조물 HUD | 온라인에서는 `buildSupported=false` |
| 장비 상세 | 비교·특수 옵션 효과 풀 미완성 |
| 브라우저 입력 | 온라인 전송 계층이 Space를 대시 비트 `4`가 아닌 Q 비트 `1`로 보내는 결함 존재 |
| E2E | 실제 브라우저 3개를 사용한 전체 원정 검증 부재 |

일반 인게임 실행은 서버 권위 경로만 사용한다. 로컬 `editor-core`는 맵 편집기 플레이 테스트 전용 개발 도구이며 일반 플레이 대체 경로가 아니다.

## 12. 완료 기준

현재 빌드의 다음 릴리스 완료 조건은 다음과 같다.

1. 온라인 Space 대시 입력 계약을 수정하고 브라우저 입력 통합 테스트를 추가한다.
2. 건설을 구현하거나 프로토콜·UI에서 공식적으로 제거한다.
3. 세 브라우저에서 로비, 분산 탐색, 웨이포인트, 재접속, 개인 상태 격리, 결과 저장을 검증한다.
4. 배포 URL에서 신규 게스트가 한 원정을 종료하는 smoke test를 통과한다.
