# 게임 기획 고도화를 위한 추가 입력 제안

## 1. 현재 아이디어 진단

### 한 줄 정의

3명의 신참 용사가 25분 동안 위험 지역을 개척하고 기지를 성장시킨 뒤, 5일째 마왕을 공략하는 협동 로그라이트 디펜스 RPG.

### 강점

- **시간 압박이 분명하다.** 5일·25분이라는 제한이 탐험과 방어 사이의 선택을 만든다.
- **협동 역할이 자연스럽게 생긴다.** 낮에는 분산 탐험, 밤에는 일부 귀환이라는 흐름이 대화를 유도한다.
- **위험과 보상의 방향성이 직관적이다.** 우측 상단으로 갈수록 강해지는 적과 보상은 별도 설명 없이도 이해하기 쉽다.
- **성장 결과를 검증할 결승전이 있다.** 마지막 보스전이 25분 동안의 선택을 평가한다.

### 핵심 리스크

- 2~3일 안에 실시간 3인 동기화, 절차 생성, 5개 클래스, 계정·DB까지 모두 구현하기 어렵다.
- 탐험, 액션 전투, 디펜스, 건설, 경제가 동시에 작동하므로 규칙이 수치화되지 않으면 플레이가 산만해질 수 있다.
- 낮에 전원이 탐험하고 밤에 일부만 방어할 때, 방어 담당자의 경험이 반복 작업으로 느껴질 수 있다.
- 랜덤 맵이 핵심 자원이나 게이트 접근을 막으면 실력보다 운이 승패를 좌우할 수 있다.
- 25분 세션은 개발 중 반복 테스트가 느리다. 8~10분짜리 개발용 모드가 필요하다.

## 2. 우선 결정이 필요한 입력

아래 항목은 구현과 밸런스에 미치는 영향이 큰 순서다. 괄호 안은 초안에 적용한 권장 기본값이다.

| 우선순위 | 결정 항목 | 선택 또는 입력할 내용 | 권장 기본값 |
|---|---|---|---|
| P0 | MVP 성공 기준 | 발표에서 반드시 보여줄 한 가지 재미 | 탐험과 기지 방어 사이의 협동 판단 |
| P0 | 실제 인원 조건 | 반드시 3인이 필요한지, 1~2인 테스트를 지원할지 | 1~3인, 빈 슬롯은 난이도 보정 |
| P0 | 전투 조작 | 이동, 기본 공격, 스킬, 조준 방식 | WASD + 포인터 조준 + 기본 공격 + 스킬 2개 |
| P0 | 네트워크 범위 | 서버 권위 범위와 동기화 대상 | 방·플레이어·적·자원만 동기화, 계정은 후순위 |
| P0 | 맵 규모 | 구역별 방 수와 한 화면 전투 여부 | 3구역, 구역당 핵심 방 4개 |
| P0 | 경제 단위 | 자원 종류와 개인/공용 여부 | 골드 1종 공용, 경험치 개인 |
| P0 | 건설 범위 | 시설 종류, 위치, 업그레이드 방식 | 지정 슬롯에 포탑·장벽 각 1종 |
| P0 | 패배 복구 | 사망 손실과 부활 시간 | 소지 골드 30% 드롭, 5초 후 부활 |
| P1 | 클래스 수 | 실제 구현할 클래스와 차별점 | MVP 3종, 확장 5종 |
| P1 | 하루 길이 | 낮/밤/정산의 정확한 초 단위 | 낮 210초, 밤 75초, 정산 15초 |
| P1 | 보스 진입 | 조기 도전, 실패 후 재도전 가능 여부 | 4일차부터 투표로 입장, 전멸 시 1회 후퇴 |
| P1 | 성장 선택 | 레벨업 선택지 수와 등급 | 3개 중 1개, 공용 풀 + 클래스 풀 |
| P1 | 로그라이트 메타 | 영구 강화가 수치인지 콘텐츠 해금인지 | 신규 특성 해금 중심, 영구 능력치는 소폭 |
| P1 | 랜덤 보정 | 필수 방·자원 보장 규칙 | 구역별 게이트·웨이포인트·회복 방 보장 |
| P2 | 서사 톤 | 코믹/진지 비율과 캐릭터 대사량 | 경쾌한 신참 용사 코미디 |
| P2 | 아트 제약 | 타일 크기, 해상도, 에셋 출처 | 16px 또는 32px 타일, 단일 팔레트 |
| P2 | 계정 기능 | 로그인과 방명록이 핵심 시연에 필요한지 | MVP 제외, 로컬 닉네임만 사용 |

## 3. 기획자가 추가로 답하면 좋은 질문

### 핵심 경험

1. 플레이어가 세션 종료 후 가장 많이 이야기하길 바라는 순간은 무엇인가?
2. 조작 실력, 빌드 설계, 협동 의사결정 중 승패에 가장 큰 영향을 줄 요소는 무엇인가?
3. 한 명이 팀을 이끄는 구조와 세 명이 동등하게 제안하는 구조 중 어느 쪽을 원하는가?

### 전투와 클래스

1. 공격은 자동, 반자동, 수동 중 무엇인가?
2. 피격 회피 중심인지, 스탯으로 버티는 전투인지?
3. 클래스 변경은 로비에서만 가능한가, 세션 중 전직이 가능한가?
4. 세 클래스가 같은 아이템을 두고 경쟁할 수 있는가?

### 디펜스와 타이쿤

1. 시설 배치는 자유 배치인가, 지정 슬롯 방식인가?
2. 포탑이 적을 대부분 처리해야 하는가, 시간을 벌어주는 역할인가?
3. 기지 성장은 자동화 생산, 방어 강화, 플레이어 강화 중 어디에 초점을 두는가?
4. 공용 자원 소비는 한 명이 즉시 집행하는가, 팀 투표가 필요한가?

### 세션과 메타 성장

1. 한 세션 실패 시에도 반드시 얻는 보상은 무엇인가?
2. 영구 성장으로 보스 난이도가 무너지는 것을 어떻게 막을 것인가?
3. 신규 플레이어와 숙련 플레이어가 함께 플레이할 때 난이도는 누구를 기준으로 하는가?

### 기술과 운영

1. 로컬 시연인지 인터넷 배포인지?
2. 모바일 브라우저를 지원하는지?
3. 서버와 DB를 실제 배포해야 하는지?
4. 아트·사운드 에셋을 직접 제작할지, 라이선스 에셋을 사용할지?

## 4. 2~3일 MVP 범위 권고

### 반드시 구현

- 1개의 방에 1~3인 접속 및 이동·공격 동기화
- 3개 구역으로 이어지는 고정 골격 + 일부 방 배치 랜덤화
- 낮/밤 5일 타이머와 밤 웨이브
- 클래스 3종, 각 기본 공격 1개와 액티브 스킬 2개
- 골드 획득, 지정 슬롯 건설, 시설 업그레이드
- 게이트 파괴, 웨이포인트, 사망·부활·자원 드롭
- 최종 보스 1종과 승리·패배 화면

### 시간 여유가 있을 때

- 히든 몬스터와 희귀 보상
- 클래스 2종 추가
- 맵 시드 공유와 결과 통계
- 간단한 영구 해금

### 후속 버전으로 이관

- 회원가입·로그인·PostgreSQL
- 방명록
- 정교한 매칭과 재접속
- 다수 보스·바이옴·서사 이벤트
- 본격적인 영구 스탯 트리

## 5. 고도화 초안에 적용한 가정

- PC 웹을 우선하며 키보드와 마우스를 사용한다.
- 3인 협동이 목표지만 개발과 시연을 위해 1~2인도 시작할 수 있다.
- 기지는 공용, 경험치와 전투 빌드는 개인, 건설 골드는 공용이다.
- 맵은 완전 절차 생성이 아니라 검증된 방 템플릿을 규칙에 따라 섞는다.
- 타이쿤 요소는 복잡한 생산 체인보다 제한된 골드의 투자 우선순위에 집중한다.
- MVP에서는 계정·DB보다 한 세션의 완결성과 멀티플레이 안정성을 우선한다.
