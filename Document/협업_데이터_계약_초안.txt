[문서 정보]
- 이름: 0.2 협업 데이터 계약 초안
- protocolVersion: 2
- 런타임: Next.js Node / Colyseus / PostgreSQL
- 원칙: 클라이언트는 의도를 전송하고, 서버가 상태와 결과를 확정한다.
- 실제 스키마 원본: packages/protocol/src/index.ts
- 순수 규칙 원본: packages/game-core/src/v02/

[공통 ID 규칙]
- 클래스: swordsman / archer / mage
- 파티 모드: solo / coop
- 세션 모드: prototype / full
- 난이도: easy / normal / hard
- 페이즈: lobby / day / night / standby / boss / ended
- 방: start / gate / resource / static-monster / empty / central-waypoint / hidden-monster
- 시설: turret / wall
- 장비 슬롯: weapon / armor / accessory
- 희귀도: normal / rare / epic / legendary / mythic
- 결과: victory / defeat / abandoned / server_error
- 데이터 ID: lower-kebab-case
- network ID: Room 안에서 유일한 1~96자 문자열
- 사용자·match·DB ID: UUID
- 시간: 문서 초, protocol clientTime ms, cooldown/holdDuration ms
- 수치: HP·피해·방어·골드·XP는 최종 정수

[RoomOptions v2]
- heroClass: swordsman | archer | mage
- sessionMode: prototype | full
- difficulty: easy | normal | hard
- partyMode: solo | coop
- protocolVersion: 반드시 2
- solo는 최대/시작 1명, coop은 최대/시작 정확히 3명
- partyMode/sessionMode/difficulty가 다른 사용자는 같은 Room에 참가할 수 없음
- 진행 시작 후 신규 중도 참가 금지, 기존 사용자 재접속만 허용

[명령 Envelope]
모든 명령은 아래 필드를 가진 strict object다.
- v: 2
- seq: 연결별 0부터 단조 증가하는 안전한 정수
- clientTime: 0 이상의 유한한 number; 관측용이며 판정 시간으로 신뢰하지 않음
- type: 아래 허용 type 중 하나
- payload: type별 strict object

서버 공통 검증:
- protocol version 불일치 거부
- 알 수 없는 필드와 type 거부
- 직렬화 크기 4KiB 초과 거부
- 사용자당 초당 30개 초과 제한
- 마지막 처리 seq 이하의 중복/out-of-order 명령 거부
- 다른 Room·사용자 소유 network ID 거부

[ClientCommand v2]
1. room.ready
   payload: { ready: boolean }
   검증: lobby에서만, solo1/coop3 전원 준비 시 시작

2. player.input
   payload: { x: -1..1, y: -1..1, aim: -2PI..2PI, buttons: 0..31 }
   검증: 축 정규화, 생존·연결·진행 phase, 속도 한계
   주의: aim은 자동 공격 후보 계산에 사용하고 클라이언트 target은 받지 않음

3. skill.cast
   payload: { skillId: q|e|dash, targetX: number, targetY: number }
   검증: 클래스, cooldown, 방, 사거리, 생존, target 좌표

4. player.interact
   payload: { targetId: networkId }
   검증: 같은 방, 상호작용 거리, target 상태

5. travel.request
   payload: { waypointId: networkId, destinationId: networkId }
   검증: 활성 waypoint, 유효 목적지, connected+alive 전원 점유, 5초 유지

6. recall.request
   payload: {}
   검증: boss/사망/전투 제한과 최종 귀환 정책

7. upgrade.choose
   payload: { draftId: UUID, upgradeId: 1~64자 }
   검증: 해당 사용자의 현재 active draft, 3개 choices 안의 ID, stack 상한

8. equipment.equip
   payload: { dropId: networkId }
   검증: 개인 소유 drop, 미중복 수령, 슬롯, 현재 Room/거리 정책

9. build.place
   payload: { buildingId: turret|wall, gridX: 0..24, gridY: 0..16 }
   검증: 건설 구획, 골드, 점유, 충돌, 길 완전 차단 금지

10. build.upgrade
    payload: { structureId: UUID }
    검증: 같은 Room, 상호작용 거리, 비용, 최대 레벨, 중복 명령

[서버 이벤트]
- message: 사용자 안내 메시지
- protocol-error: INVALID_MESSAGE / VERSION_MISMATCH / RATE_LIMITED / NOT_OWNER 등 오류 코드
- result: victory / defeat / abandoned와 서버 확정 reason
- 공격·피격·드롭 연출 이벤트는 서버 규칙 통합 시 protocol v2에 명시적으로 추가

[PartyRoomState 최소 루트]
- protocolVersion, matchId, seed
- phase, currentZone, day, serverTime, phaseEndsAt
- baseHp, baseMaxHp, gold
- teamLevel, teamXp, teamXpToNext
- players: Map<PlayerState>
- rooms: Map<RoomState>
- doors: Map<DoorState>
- enemies: Map<EnemyState>
- waypoints: Map<WaypointState>
- structures: Map<StructureState>
- drops: Map<DropState>

[PlayerState 최소 필드]
- userId, displayName, heroClass
- roomId, x, y, aim
- hp, maxHp, level, teamPower
- ready, connected, alive
- equipment: weapon/armor/accessory ID·rarity와 적용 bonus 요약
- upgradeDraft: draftId, level, active, expiresAt, choices[3]

[Room / Door]
- RoomState: id, zone, gridX, gridY, kind, depth, discovered, cleared
- DoorState: id, zone, fromRoomId, toRoomId, open, locked
- 시작 좌표: (0,4), 게이트 좌표: (4,0)
- 모든 방은 start에서 도달 가능
- hidden-monster 방 연결은 정확히 1개

[EnemyState]
- id, kind, behavior
- roomId, spawnRoomId, targetId
- x, y, hp, maxHp, alive
- 정적 몬스터는 피격 전 target 없음
- 동적 몬스터 targetId에 player ID 사용 금지

[WaypointState]
- id, roomId, kind, destinationId, active
- requiredPlayers, holdingPlayers
- holdProgress, holdDurationMs=5000
- requiredPlayers는 현재 connected && alive 실제 사용자 수
- 한 명이라도 조건 이탈 시 holdProgress=0

[StructureState]
- id, roomId, kind, ownerUserId
- gridX, gridY, level, hp, maxHp
- 팀 자원이므로 ownerUserId는 생성자 추적용이며 독점 소유권을 의미하지 않음

[DropState]
- id, roomId, itemId, slot, rarity, x, y
- specialOptionCount, claimed
- 구현 시 ownerUserId 또는 개인별 비공개 상태를 반드시 추가해 소유권 검증
- 히든 개인 드롭: Legendary 80% / Mythic 20%, 적격 사용자당 1개

[결정론 계약]
- map seed: runSeed + zone
- hidden drop seed: runSeed + zone + hiddenRoomId + playerId + dropIndex
- augment draft seed: runSeed + playerId + heroClass + level + draftIndex + stack signature
- 같은 입력은 런타임/브라우저와 무관하게 같은 결과를 생성
- PRNG는 보안용이 아니며 게임 재현 전용
- 랜덤 알고리즘 변경 시 serverVersion과 변경 로그에 재현성 영향을 기록

[서버 권위]
서버 소유:
- Room·페이즈·시간·seed·맵
- 이동 유효성·방 전환·충돌
- 자동 공격 대상·공격 주기·피해·HP
- 적 AI·스폰·리스폰·target
- 팀 골드·자원 tick·건설
- XP·레벨·draft·stack
- 드롭·희귀도·개인 소유·장착
- waypoint 정족수·5초 진행·보스 입장
- 승패·통계·DB 결과

클라이언트 소유:
- 입력 수집
- Phaser 렌더링·카메라·사운드·이펙트
- React HUD·로비·선택 UI
- 로컬 이동 예측과 서버 보정 표현

클라이언트가 전송하지 않는 값:
- 사용자 ID·표시 이름의 신뢰값
- 현재 HP·최종 피해·골드·XP
- 드롭 rarity·옵션
- 타이머·승패·결과 통계

[저장 계약]
- PostgreSQL: users, auth_sessions, guestbook_entries, matches, match_players
- match 생성과 종료는 game-server가 수행
- 결과는 하나의 transaction으로 한 번만 확정
- 실시간 entity tick은 PostgreSQL에 저장하지 않음
- 장비 영구 저장은 현재 0.2 범위 결정 전이며 런 상태를 기본으로 함
