# AI가 통로에서 반대 방향으로 이동하거나 멈추는 문제

## 현상

공식 맵에서 동료 AI의 목표가 다른 방으로 변경될 때 다음 현상이 발생했다.

- 목표와 반대 방향의 출입구로 되돌아간다.
- 통로 중간에서 거의 움직이지 않는 것처럼 보인다.
- 특히 목표까지의 직선거리가 약 560 월드 단위일 때 재현된다.

진단 계측에서는 AI가 실제로 완전히 정지한 것이 아니라 매 시뮬레이션 틱마다 다음 두 상태를 왕복했다.

```text
x=1347.430, 목표까지 547.430, 입력 방향 -X
x=1360.180, 목표까지 560.180, 입력 방향 +X
```

## 영향 범위

- 영향 대상: 서버 권위 동료 AI(`aiRole: follower`)의 리더 추종
- 영향 맵: 벽과 꺾인 통로를 포함하는 authored/공식 맵
- 비영향 대상: 몬스터방의 정적 몬스터
- 별도 경로 체계: 게이트 침입자는 방 그래프와 authored 통로 점을 사용하며 동료 A*와 같은 구현을 사용하지 않는다. 기존 방 그래프 탐색은 통로 길이가 아닌 방 수를 비용으로 사용했다.

## 원인

### 1. A* 사용 여부를 직선거리로 결정

기존 코드는 AI와 리더 사이의 유클리드 직선거리가 `560` 미만이면 활성 A* 경로를 삭제했다. 하지만 직선거리는 두 지점 사이에 벽이 있는지, 통로가 몇 번 꺾이는지 표현하지 못한다.

따라서 공간상으로는 가깝지만 벽 반대편인 경우에도 A*가 해제되고 AI가 목표를 향해 직선으로 이동하다 벽에 막혔다.

### 2. 통로 웨이포인트를 처음부터 재시작

액터가 통로에 들어가도 다음 방 사각형에 완전히 진입하기 전까지 논리 `roomId`는 출발 방으로 유지된다. 이 상태에서 A*가 해제되면 authored 통로 추종이 `waypointIndex = 0`으로 다시 시작됐다.

AI가 이미 첫 출입구를 통과했더라도 첫 웨이포인트가 다시 목표가 되어 반대 방향으로 이동했다.

### 3. 경계값에서 두 제어기가 번갈아 활성화

직선거리 560에 진입/해제 히스테리시스가 없었다. 한 틱에는 A*가 베이스 방향을 지시하고 다음 틱에는 초기화된 통로 추종이 반대편 출입구를 지시했다. 두 이동량이 거의 같아 화면에서는 멈춘 것으로 보였다.

## A* 거리 계산 확인

A* 자체는 직선거리만으로 경로를 선택하지 않는다.

- `g`: 현재까지 통과한 그리드 간 실제 이동거리의 누적값
- `h`: 현재 노드에서 목적지까지의 직선거리 추정값
- `f = g + h`: 우선 탐색 순서

대각선과 직선 이동 모두 실제 구간 길이를 `g`에 더하며, 각 구간은 액터 충돌 원이 이동 가능한지 검사한다. 마지막에는 벽을 통과하지 않는 범위에서만 경로를 스무딩한다. 따라서 L자·U자 통로에서는 꺾인 구간의 실제 누적거리를 따라 목적지에 도달한다.

문제는 A* 내부 비용 함수가 아니라 A*와 authored 통로 추종 사이를 전환하는 조건이었다.

게이트 침입자에는 별도의 문제가 있었다. 기존 BFS는 모든 방 연결 비용을 1로 보므로, 세 개의 짧은 통로보다 두 개의 매우 긴 우회 통로를 선택할 수 있었다. 이는 직선거리 기반 문제는 아니지만 가변 맵에서 실제 이동거리와 최단 방 경로가 달라지는 원인이 된다.

## 수정 내용

### 직접 이동 가능성으로 전환 판단

직선거리 임계값을 제거했다. 액터의 전체 충돌 원이 현재 위치에서 리더까지 벽 없이 이동 가능한 경우에만 A*를 생략한다.

- 직접 이동 가능: 리더 좌표를 향해 바로 이동
- 벽 또는 꺾인 통로로 차단: 거리에 관계없이 A* 계산
- 같은 방에서 이미 추종 간격 안: 이동 중단

이로써 가까운 벽 반대편 목표도 통로를 따라 우회한다.

### 현재 위치에서 통로 진행 재개

authored 통로 상태를 새로 만들 때 인덱스를 항상 0으로 설정하지 않는다. 현재 위치에서 충돌 없이 도달 가능한 가장 먼 통로 점을 찾아 그 지점부터 추종한다.

통로 중간에서 목표가 변경되거나 A* 경로가 갱신되어도 이미 지나온 출입구로 돌아가지 않는다.

### 충돌 안전 직선 검사 공유

`isWalkableDiscLine`을 공용 함수로 노출해 A* 경로 생성과 AI 제어기 전환 판단이 동일한 충돌 반경 및 이동 가능 지형을 사용하도록 했다.

### 게이트 침입자 경로를 실제 통로 길이로 가중

게이트 침입자의 최단 방 탐색을 홉 수 BFS에서 가중 최단 경로 탐색으로 변경했다. 각 연결 비용은 다음 거리의 합이다.

1. 출발 방 중심에서 출발 출입구까지
2. authored 통로의 모든 꺾인 폴리라인 구간
3. 도착 출입구에서 도착 방 중심까지

따라서 방을 하나 더 지나더라도 실제 통로 이동거리가 짧은 경로를 선택한다. 재탐색이 통로 중간에서 발생했을 때도 현재 위치에서 도달 가능한 가장 앞선 통로 점부터 재개해 이전 출입구로 역주행하지 않는다.

## 회귀 테스트

다음 시나리오를 자동화했다.

1. L자 지형에서 직선 이동이 막힌 동료가 A* 경로로 모서리를 돈다.
2. 공식 맵에서 리더를 베이스에서 게이트로 이동시켜 동료를 통로 쪽으로 유도한다.
3. 동료가 이동 중일 때 리더를 다시 베이스로 이동한다.
4. 동료가 560 거리 경계에서 왕복하지 않고 공식 통로를 따라 베이스 방에 진입하는지 확인한다.
5. 리더와 동료의 최종 거리가 정상 추종 범위인지 확인한다.
6. 두 방짜리 장거리 우회로와 세 방짜리 단거리 통로가 함께 있을 때 게이트 침입자가 실제 이동거리가 짧은 세 방 경로를 선택하는지 확인한다.

실행 명령:

```bash
node --import tsx --test packages/game-core/test/world-navigation.test.ts
```

## 추가 진단 체크리스트

비슷한 문제가 다시 발생하면 다음 값을 함께 기록한다.

- AI와 목표의 월드 좌표 및 `roomId`
- 현재 A* 웨이포인트와 `waypointIndex`
- authored 통로의 방향(`from`, `to`)과 통로 점 배열
- `isWalkableDiscLine` 결과
- 틱별 입력 벡터 `inputX`, `inputY`
- 목표 변경 또는 리더 사망·재생성 시각

게이트 침입자가 반대 방향으로 이동한다면 동료 A*가 아니라 침입자의 플레이어 어그로 전환, 가중 방 그래프 경로, blocked-edge 재탐색 상태를 별도로 점검해야 한다.
